# 弹幕数据服务与主播网站开发计划

状态：已确认，待实施  
更新日期：2026-09-01

## 1. 产品定位

项目拆分为两个边界清晰的部分：

1. `huya-danmu` 是部署在国内服务器上的弹幕数据服务，负责长期采集、持久化、统计分析、归档和 API。
2. 现有主播主题网站是面向访客的内容前端，负责图表、排行、词云、弹幕墙、梗库和主播相关内容的展示。

监听、统计和文本分析逻辑不得放入访客浏览器；前端不得直接连接 PostgreSQL。当前运维管理页面继续保留，但不作为公开网站使用。

```text
虎牙直播间
    ↓
国内服务器：huya-danmu
├── 开播检测与普通弹幕采集
├── PostgreSQL 与归档
├── 关键词、短语、排行和生命周期计算
├── 私有管理后台
└── 公开只读 API / SSE
          ↓
主播主题网站
├── 实时弹幕墙
├── 今日、本场和历史排行
├── 弹幕趋势与统计卡片
├── 关键词词云
└── 精选梗库与年度榜单
```

## 2. 后端职责

`huya-danmu` 继续采用单体 Node.js 服务和 PostgreSQL，单主播阶段不拆微服务。它负责：

- 后台自动检测开播、下播并维护直播场次。
- 只持久化普通文本弹幕，不保存礼物和人气通知。
- 保存原始弹幕并维护分钟、每日和场次聚合。
- 中文分词、停用词过滤、高频关键词和短语统计。
- 检测复读、突发词和弹幕高峰。
- 计算词语或梗的新生、爆发、常青、衰退和消失阶段。
- 提供私有管理 API、公开只读 API 和实时 SSE。
- 执行数据归档、备份、容量监控和完整度检查。

若后续文本分析任务明显影响采集稳定性，再在同一仓库增加独立 worker 容器，不提前引入分布式架构。

## 3. 前端职责

现有主播主题网站通过 API 使用数据，并保持自己的视觉风格。计划加入：

- 当日、本场、最近 7 日和最近 30 日统计卡片。
- 每分钟弹幕量及独立发言人数趋势。
- 5 分钟、1 小时、本场、当日、7 日和 30 日排行。
- 实时原始弹幕墙和最近 5 分钟热榜。
- 高频关键词、短语和 Emoji 排行。
- 可点击词云：进入趋势和原始弹幕搜索结果。
- 突发词、复读率和高潮时间段。
- 梗生命周期、人工精选梗和年度榜单。
- 一键复制和生成分享图片。

不使用 iframe 嵌入管理页面，不在公开前端中保存管理员令牌。

## 4. API 分级

### 4.1 私有管理 API

沿用 `/api/v1/*` 和 `ADMIN_API_TOKEN`，用于房间管理、归档、重建统计和系统状态。生产环境只允许内网、VPN 或可信管理入口访问。

### 4.2 公开只读 API

新增独立命名空间，候选接口如下：

```http
GET /api/public/v1/live
GET /api/public/v1/summary?date=2026-09-01
GET /api/public/v1/top-messages?window=day&limit=10
GET /api/public/v1/message-counts?interval=5m
GET /api/public/v1/keywords?window=day
GET /api/public/v1/emerging-phrases
GET /api/public/v1/meme-lifecycle
GET /api/public/v1/stream
```

公开接口必须满足：

- 只读，不能添加、暂停或删除监听房间。
- 不返回发送者 UID 等不必要的用户标识。
- 参数白名单、查询时间范围限制和响应条数上限。
- 按 IP 限流，并对统计结果缓存 10～60 秒。
- CORS 只允许主播网站域名；本地开发域名单独配置。
- 全部通过 HTTPS；实时数据优先采用 SSE。
- API 版本化，避免前端升级被后端变更破坏。

如果主播网站拥有自己的服务端，优先由其服务端调用私有的只读接口；如果是纯静态 SPA，则使用上述公开接口。任何放入浏览器的 Token 都不视为秘密。

## 5. 统计口径

公开页面需要明确区分两类排行：

1. 真实发言排行：来自虎牙直播间的实际发送次数。
2. 社区热度排行：未来可能产生的复制、收藏、点赞次数。

两种指标不得混合成同一个“热度”。当前优先实现真实发言排行。

建议新增或扩展以下聚合数据：

- `keyword_stats`：关键词的分时段统计。
- `phrase_stats`：短语首次出现、最后出现、累计次数和涉及场次数。
- `phrase_lifecycle`：生命周期阶段、趋势分和计算时间。
- `curated_memes`：人工精选文本、标签、说明和展示状态。
- `public_daily_summary`：供公开网站快速读取的每日摘要。

最终表结构应在实现阶段结合现有分钟和每日聚合表确定，避免重复保存可低成本计算的数据。

## 6. 分阶段实施

### 阶段 A：公开数据基础

- 新增公开只读 API 命名空间。
- 增加 CORS、限流、缓存和隐私字段过滤。
- 完成接口契约、错误格式和 OpenAPI 文档。
- 为公开接口补充自动化测试。

验收标准：公开网站无需管理员令牌即可安全读取指定统计，但不能执行任何写操作或获取用户 UID。

### 阶段 B：基础网站集成

- 在主播网站接入今日 TOP10。
- 增加本场/今日统计卡片。
- 增加弹幕量趋势图和时间范围筛选。
- 点击某个分钟可查看该时段弹幕。

验收标准：网站能稳定展示真实数据，接口故障时有明确的降级和空状态。

### 阶段 C：实时体验

- 增加 SSE 实时弹幕接口。
- 实现实时弹幕墙、连接状态和自动重连。
- 增加最近 5 分钟排行和突发弹幕标识。

验收标准：页面断线重连不会重复显示事件，服务重启后历史统计不受影响。

### 阶段 D：文字分析

- 中文分词、停用词管理和关键词排行。
- 高频短语、Emoji、复读率和突发词。
- 可点击词云及关键词历史趋势。
- 展示数据完整度和采集断线区间。

验收标准：分词结果可解释、可通过停用词调整，所有分析均可追溯到原始弹幕和明确时间范围。

### 阶段 E：内容产品化

- 自动生成候选梗。
- 管理员确认、标记和维护精选梗。
- 实现生命周期、年度榜单、复制和分享图片。
- 如有需求，再单独统计社区复制、收藏和点赞行为。

验收标准：原始统计和社区热度保持分离，人工修改不会污染历史弹幕数据。

## 7. 暂不开发

- 用户注册和完整社区体系。
- 站内聊天室、签到、积分、勋章和小游戏。
- 赛事竞猜、音乐、相册等非核心功能。
- AI 自动造梗或未经验证的情感分析。
- 多主播和多节点高可用。
- 浏览器直接连接虎牙作为正式采集方式。

这些功能只有在核心数据页面稳定、真实用户需求明确后再评估。

## 8. 下一步输入

开始阶段 A 前，需要补充主播主题网站的：

- 仓库地址和前端技术栈。
- 当前部署方式、域名和是否存在网站后端。
- 期望公开展示的页面位置和视觉风格。
- 是否仅自己使用，还是面向所有访客开放。

拿到这些信息后，先确定 API 契约和页面线框，再开始实现。
