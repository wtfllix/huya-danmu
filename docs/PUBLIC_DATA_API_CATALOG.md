# 主播网站可用数据与公开 API 提案

状态：供网站产品形态分析，尚未实现公开接口  
日期：2026-09-01  
默认时区：`Asia/Shanghai`

## 1. 给网站侧 Agent 的结论

`huya-danmu` 可以作为主播网站的只读数据源。网站无需承担虎牙连接、弹幕采集、统计或中文文本分析，也不得直接连接 PostgreSQL。

当前后端已经保存或统计的数据包括：直播状态、直播场次、原始普通文本弹幕、分钟弹幕量、每日弹幕总量、每日高频弹幕文本和采集时间。公开 API 尚未实施；本文定义的是建议契约，网站侧可据此分析页面、组件和交互形态。

数据能力分为三类：

- `现有`：数据库已有，可在阶段 A 直接封装成公开 API。
- `可派生`：可从现有原始数据计算，但可能需要新增聚合字段或查询缓存。
- `后续`：需要新增分析逻辑或数据表，不应作为首版网站的硬依赖。

## 3. 建议的公开 API

统一前缀：`/api/public/v1`。以下均为只读 `GET` 请求，不使用管理员令牌。

### 3.1 阶段 A：首版即可提供

#### `GET /live`

获取主播与当前直播/采集状态。

建议响应：

```json
{
  "room_id": "1995",
  "anchor_name": "示例主播",
  "live_status": "live",
  "collector_status": "listening",
  "title": "今晚直播标题",
  "category": "主机游戏",
  "session_id": "9f7c...",
  "started_at": "2026-09-01T11:58:00+08:00",
  "last_message_at": "2026-09-01T12:34:56.789+08:00",
  "data_freshness": "realtime"
}
```

`live_status` 建议只公开 `live | offline | unknown`；内部的连接状态另放在 `collector_status`，可取 `listening | connecting | degraded | idle`。

#### `GET /summary`

获取统计卡片所需摘要。

查询参数：

- `scope`：`session | day | 7d | 30d`，默认 `day`。
- `date`：`YYYY-MM-DD`；仅 `scope=day` 使用，默认今天。
- `session_id`：可选；仅 `scope=session` 使用，默认当前场次。

建议响应：

```json
{
  "scope": "day",
  "from": "2026-09-01T00:00:00+08:00",
  "to": "2026-09-02T00:00:00+08:00",
  "message_count": 38642,
  "unique_senders": 4281,
  "peak": {
    "bucket_at": "2026-09-01T21:17:00+08:00",
    "message_count": 326
  },
  "active_session_count": 1,
  "data_complete": true
}
```

`unique_senders` 和 `data_complete` 首版若尚未完成，可返回 `null`，不能用 `0` 冒充未知。

#### `GET /message-counts`

获取弹幕量时间序列。

查询参数：

- `from`、`to`：带时区的 ISO 8601，使用半开区间 `[from, to)`，必填。
- `interval`：`1m | 5m | 15m | 1h | 1d`，默认 `5m`。
- `session_id`：可选，仅统计指定场次。

建议响应：

```json
{
  "from": "2026-09-01T20:00:00+08:00",
  "to": "2026-09-01T21:00:00+08:00",
  "interval": "5m",
  "items": [
    { "bucket_at": "2026-09-01T20:00:00+08:00", "message_count": 812 },
    { "bucket_at": "2026-09-01T20:05:00+08:00", "message_count": 0 }
  ]
}
```

没有弹幕的时间桶也必须返回，`message_count` 为 `0`。

#### `GET /top-messages`

获取真实发言频次排行，不表示点赞或社区热度。

查询参数：

- `window`：`5m | 1h | session | day | 7d | 30d`，默认 `day`。
- `date`：`window=day` 时可选，格式 `YYYY-MM-DD`，默认今天。
- `session_id`：`window=session` 时可选，默认当前场次。
- `at`：`5m` 或 `1h` 窗口的结束时间；默认当前时间。
- `limit`：`1～50`，默认 `10`。

建议响应：

```json
{
  "window": "day",
  "from": "2026-09-01T00:00:00+08:00",
  "to": "2026-09-02T00:00:00+08:00",
  "total_messages": 38642,
  "items": [
    { "rank": 1, "content": "666", "message_count": 972, "share": 0.0252 }
  ]
}
```

完整弹幕文本的统计口径为去除首尾空白并执行 Unicode NFC；不忽略大小写，不合并标点或不同 Emoji。同次数时按规范化文本升序，保证结果稳定。

#### `GET /messages`

获取某个时段的公开弹幕，用于时段详情、搜索结果或非实时弹幕墙。

查询参数：

- `from`、`to`：可选；公开接口建议单次范围最多 24 小时。
- `session_id`：可选。
- `keyword`：可选，建议长度 `1～50`。
- `cursor`：可选，不透明游标。
- `limit`：`1～100`，默认 `50`。
- `order`：`asc | desc`，默认 `desc`。

建议响应：

```json
{
  "items": [
    {
      "id": "evt_01J...",
      "session_id": "9f7c...",
      "occurred_at": "2026-09-01T20:15:02.381+08:00",
      "sender_name": "观众昵称",
      "content": "这段太好笑了"
    }
  ],
  "next_cursor": "opaque-token",
  "has_more": true
}
```

不得返回发送者 UID、原始协议载荷、内容哈希或数据库内部字段。是否展示昵称应作为部署配置；若关闭，则省略 `sender_name` 或返回统一的“观众”。

#### `GET /sessions`

获取直播场次列表，供历史场次选择。

查询参数：

- `cursor`：可选。
- `limit`：`1～50`，默认 `20`。

建议响应：

```json
{
  "items": [
    {
      "id": "9f7c...",
      "status": "completed",
      "started_at": "2026-08-31T19:58:00+08:00",
      "ended_at": "2026-09-01T00:21:00+08:00",
      "title": "直播标题",
      "category": "主机游戏",
      "message_count": 52880
    }
  ],
  "next_cursor": null,
  "has_more": false
}
```

### 3.2 阶段 C：实时数据

#### `GET /stream`

使用 Server-Sent Events 推送实时普通文本弹幕及状态变化。

建议事件类型：

- `hello`：连接建立，返回当前 `session_id` 和心跳间隔。
- `danmu`：新弹幕，只含公开字段。
- `live_status`：开播、下播或状态未知。
- `collector_status`：采集连接状态变化。
- `heartbeat`：保活事件。

示例：

```text
id: evt_01J...
event: danmu
data: {"id":"evt_01J...","session_id":"9f7c...","occurred_at":"2026-09-01T20:15:02.381+08:00","sender_name":"观众昵称","content":"666"}
```

客户端使用 SSE 的 `Last-Event-ID` 断线续接；服务端只补一个短窗口，超出窗口后发送 `reset`，客户端再通过 `/messages` 补取。事件 ID 必须稳定，重连后同一事件不得生成新 ID。

### 3.3 阶段 D：文字分析

#### `GET /keywords`

参数建议：`window`、`date`、`session_id`、`at`、`limit`。返回关键词、出现次数、涉及消息数、较前一窗口变化率及趋势序列。

#### `GET /phrases`

参数同 `/keywords`，返回短语或 Emoji、次数、消息占比、首次/最后出现时间。

#### `GET /emerging-phrases`

返回当前窗口相对历史基线明显突发的词或短语，包括 `current_count`、`baseline_count`、`burst_score` 和可解释的窗口范围。

#### `GET /repetition`

返回指定窗口的复读消息数、总消息数、复读率，以及主要复读内容。

#### `GET /incidents`

返回采集断线或数据异常区间；只公开时间、类型和数据完整度，不公开服务器错误栈等运维细节。

### 3.4 阶段 E：梗库

#### `GET /memes`

人工审核后的公开梗列表，支持标签、年份、状态和分页筛选。

#### `GET /memes/:id`

返回梗正文、说明、标签、首次/最后出现时间、累计次数、涉及场次和生命周期趋势。

#### `GET /meme-lifecycle`

返回候选词或精选梗的 `new | rising | evergreen | declining | dormant` 阶段及可解释的趋势分。

## 4. 通用契约

### 4.1 时间与数字

- API 时间统一为带时区的 ISO 8601；自然日按 `Asia/Shanghai`。
- 查询范围统一为半开区间 `[from, to)`。
- 计数在 JSON 中返回 number；若未来可能超过 JavaScript 安全整数，再统一迁移为十进制字符串。
- 未知值返回 `null`，不使用 `0`、空字符串或虚假日期代替。

### 4.2 错误格式

```json
{
  "error": {
    "code": "INVALID_PARAMETER",
    "message": "interval 只支持 1m、5m、15m、1h、1d",
    "request_id": "req_01J...",
    "details": { "parameter": "interval" }
  }
}
```

建议使用 `400` 参数错误、`404` 资源不存在、`429` 限流、`503` 数据源暂不可用。网站侧应为无数据、部分数据、服务不可用分别设计状态。

### 4.3 缓存与新鲜度

- `/live`：缓存 5～10 秒。
- `/summary`、短窗口排行：缓存 10～30 秒。
- 历史趋势、历史排行：缓存 60 秒或更久，并支持 `ETag`。
- SSE 不缓存。
- 响应建议提供 `generated_at` 和 `data_complete`，让网站能明确展示数据更新时间和缺口。

### 4.4 安全与隐私

- 公开命名空间只有 GET/HEAD/OPTIONS，不存在任何添加、暂停、删除、重建或归档接口。
- 不返回 `sender_uid`、`anchor_uid`、`raw_payload`、内部错误、磁盘路径、管理员令牌或数据库 ID。
- CORS 只允许正式网站域名和明确配置的本地开发域名。
- 按 IP 限流；搜索、原始弹幕和 SSE 使用更严格的独立配额。
- 原始弹幕是用户生成内容，网站必须按纯文本渲染，不能作为 HTML 注入页面。
- 如网站面向所有访客，建议默认不公开昵称，或在发布前完成隐私与内容治理评估。

## 5. 网站侧可优先分析的页面模块

网站形态尚未确定时，可以先围绕互不依赖的模块做方案：

1. 直播状态条：`/live`。
2. 今日/本场统计卡片：`/summary`。
3. 弹幕趋势图和高潮标注：`/message-counts`。
4. 今日或本场 TOP10：`/top-messages`。
5. 点击图表时间桶后的弹幕抽屉：`/messages`。
6. 历史直播场次浏览：`/sessions`。
7. 实时弹幕墙：后续 `/stream`，首版可轮询 `/messages` 降级。
8. 词云、突发词和梗库：阶段 D/E 能力，首版布局可以预留，但不应使用假数据作为正式功能。

网站侧 Agent 应重点回答：这些模块是放在现有主播首页、独立“弹幕数据”页面，还是作为直播期间出现的实时模式；移动端如何降级；公开昵称是否必要；默认展示“今日”还是“本场”。

## 6. 当前实现与本提案的差异

当前仓库只有受 `ADMIN_API_TOKEN` 保护的 `/api/v1/*` 管理接口，尚无 `/api/public/v1/*`。现有管理接口可读取房间、场次、原始弹幕、分钟趋势和每日排行，但会暴露内部字段，不应直接提供给公开网站。

阶段 A 实施时应优先落地 `/live`、`/summary`、`/message-counts`、`/top-messages`、`/messages` 和 `/sessions`，并通过独立序列化层过滤字段。`/stream`、关键词、短语、突发词和梗生命周期分别属于后续阶段。
